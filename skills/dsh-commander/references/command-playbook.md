# DS 4.1 指挥模板

按需读取对应段落：只读调查、明确方案实现、返工、决策答复。派发时替换为真实路径和已核实事实，删除无关字段，不传主会话全历史或隐藏推理。

## 1. 只读调查

```text
目标：查清 [症状]，让主代理能够决定 [关键决策]。
事实：[复现条件、已知现象、路径]；待核实：[假设]。
范围：仅阅读 [文件/目录]，可运行 [只读检查]；不修改文件，不运行会改数据的命令。
步骤：沿 [入口/接口] 追踪最短相关路径，区分现象与预期，必要时检查直接调用方。
交付：证据位置、根因与不确定项、至多 3 个修复方案及推荐。
完成定义：证据能区分主要假设；未复现则明确说明，不能把猜测写成事实。
升级：需要扩大范围或改环境才能继续，报告最小必要动作并结束本轮。
本轮不实施修复。
```

主代理只补读影响决策的证据，定案后续派，避免再做一遍全库调查。

## 2. 明确方案实现

```text
目标：[用户可观察的最终行为]；完成定义：[可验证交付物]。
已核实事实：[接口、路径、现状、已有改动]。
方案：[主代理决定的数据流/算法/接口要求]；不变量：[兼容性和状态边界]。
允许修改：[实际文件/目录]；禁止修改：[明确排除项]。
步骤：核实实现 → 修改 → 验证 → 修复本次引入问题 → 交付整个成果。
自主边界：局部命名、组织和兼容实现自行决定，无需每步请示。
验收：[真实命令和预期行为]；命令未知先查项目配置，不编造命令，不删测试满足验收。
升级：需要改方案/范围、缺少必要权限、或两种有证据策略均失败时，停止相关写入并报告证据和推荐。
外部操作：[准确继承用户授权，未授权不提交、推送、部署或发消息]。
完成后按协议简短交付，详细日志留在文件中。
```

### 完整示例：轮询回传优化

以下相对路径仅为示例，实际派发前须确认存在。

```text
目标：等待完成不被普通进度唤醒，同一结果不重复回传。
事实：src/manager.mjs 的 wait 监听所有 change，snapshot 每次回传累计 output；先核实当前代码是否仍如此。
方案：新增 actionable 谓词，终态/权限唤醒，普通进度仅持久化；报告以轮次 ID 标识版本，由 afterResultVersion 确认。
不变量：保留幂等、取消、原会话续派和权限；多客户端独立确认，不能用全局已读标志。
范围：只改管理器、对应工具 schema 和相关测试；不改供应商、业务代码和验收标准。
步骤：核实状态转换 → 实现等待与回包 → 行为测试 → 已有测试与构建。
自主：辅助函数和局部结构自行决定；排队轮不能掩盖已结束轮的报告。
验收：普通进度不提前结束等待；终态/权限唤醒；相同版本无重复报告；另一客户端首次仍可取得报告。先查 package.json 的真实测试/构建命令再运行。
升级：状态机不足以区分轮次和任务完成时，给最小证据及选项，停在决策点。
不提交、不推送、不重装插件、不重启服务。完成整个交付物后统一报告。
```

## 3. 返工

```text
继续同一任务。验收失败：[用例、实际与预期]。
证据：[文件:行号或最小错误输出]。
修正方向：[主代理已确定要求；不确定的原因标为待核实]。
保留约束：[仍有效且容易遗失的边界]。
只修这些失败项及直接影响，保留正确改动，不扩大重构。
重验：[命令和行为]；完成后报告本轮变化、验证及剩余问题。
```

两轮未收敛时，主代理判断事实错误、任务过大或能力不匹配，缩小问题或接管关键实现，不能只重复“再试一次”。

## 4. 决策答复

```text
针对 [问题]，选择 [选项]，依据是 [影响执行的一句话原因]。
现在允许：[用户授权内的动作]；仍禁止：[边界]。本方案决定不扩大用户授权。
接下来完成：[剩余交付物]。
验收：[确需修改时说明，否则原标准不变]。
复用已有会话与已核实事实继续，不重复调查；结束时交付证据与剩余问题。
```

## 路由

任务卡默认不写路由，即使用 `~/.dsh-commander/config.json` 的默认 `provider`/`model`。确需指定时，在 `dsh_start_task` 同时给 `provider` 与 `model`（只给一个会被拒绝），值取自 `dsh_list_routes` 返回的候选；候选只说明设置里存在，真实可用性由 DSH 在启动时确认，主代理不能把候选当作已通过证据。

路由在任务创建时冻结：同一 taskId 的 `dsh_continue_task` 永远沿用原路由，要换路由就开新任务。供应商不存在或 DSH 未确认时任务报错并不回退官方默认，此时报告缺项而不是改全局配置或凭据。

## 验收与上下文

只给任务必需的目标、路径、接口、约束和验收。允许 DS 自读相关文件；明确边界比极短却含混的提示词更能减少返工。不要用主代理通读全仓库换取任务卡完整。

优先核对真实 diff、范围、报告关键假设和高风险路径；独立检查关键行为，无需重复读整份测试日志。报告缺失、fallback 或 checks 为 not_run 时，明确缺项再决定补验。

done 是 DS 自报完成，blocked 是外部或执行阻塞，decision_required 是需主代理选择；均不替代验收、不构成新授权。
